II. SCOPE, METHODOLOGY, AND LIMITATIONS

4.  Architecture. OneWayGuard operates under strict physical and architectural constraints. It ingests unidirectional IP traffic across a hardware data diode or optical tap and has no return path into the production network. It cannot send probes, complete TCP handshakes, decrypt TLS/QUIC payloads, or perform inline blocking of any kind.

5.  Detection Method. The system extracts streaming, metadata-only features — including packet timing jitter, volume asymmetry, TCP flag dynamics, and DNS entropy — and evaluates them in near real time through a hybrid detection engine combining an adaptive Kalman filter operating on innovation residuals, a regularized XGBoost classification model, and specialist threat heuristics.

6.  Scope of Detection. The detection engine is designed to identify six threat vectors: (a) volumetric distributed denial-of-service (DDoS) activity; (b) botnet command-and-control (C2) beaconing; (c) domain generation algorithm (DGA) activity and DNS tunneling; (d) encrypted session anomalies; (e) reconnaissance and port scanning; and (f) data exfiltration.

7.  Limitations. Because the system does not inspect payload content and cannot verify traffic through active means, all findings reflect probabilistic detection based on observed metadata patterns. No finding in this report should be construed as a confirmed determination that a compromise, intrusion, or policy violation has occurred absent independent analyst verification.

How to use the detector

Generic flow model

Broad benign-versus-malicious flow model for general traffic. It is not a dedicated DDoS labeler.

Mythic HTTP C2 model

Specialized for TQH Mythic Poseidon HTTP command-and-control patterns. Do not use it as a general website verdict.

Live interface

Scapy reads packets from the selected Npcap interface, updates flows in memory, and refreshes this report every second. It never sends or blocks packets.

How a flow becomes flagged

A flag is a review signal, not proof that an attack occurred.

  1. Feature extraction: packet metadata is converted to flow features such as packet count, bytes, rate, timing, TCP flags, and packet-size statistics.
  2. Classifier score: XGBoost returns a malicious probability from 0 to 1.
  3. Kalman score: the filter compares rate, inter-arrival time, and SYN count with expected behavior and reports an anomaly score (z-score, sigma σ).
  4. Fused confidence: 0.7 × classifier probability + 0.3 × bounded Kalman anomaly. The flow is flagged ONLY when fused_confidence >= threshold.
  5. Severity: a possible volumetric event can raise severity; otherwise a flagged flow is normally medium severity.
  6. DoS/DDoS: this requires destination aggregation. Current conservative rule: at least 1,000 packets and 1,000 packets/sec; DDoS additionally needs at least 3 distinct sources.
